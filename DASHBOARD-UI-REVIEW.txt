DASHBOARD UI REVIEW — 2026-10-17

Standing instruction

Earlier dashboard decisions are recorded explicitly, including navigation, multi-meter object references, drag/resize, hover delete, Settings, styling and the unchanged protocol package.

Coverage
Reviewed the main workspace, header actions, monitoring row, value cards, trends, tables, Add OBIS picker, edit layout state, name/rename dialog, relink dialog and Settings page. The fixture uses two meters, 78 objects, restricted access, long names, long numeric values and transport-error text. Captures cover empty state, populated state, object search, no search matches, edit mode, desktop and 900x650 main-window layout, and the scrolled picker footer. Existing tests additionally cover standalone 800x600 and 1200x900 rendering, resizing, ordering, monitoring and missing-meter resolution. The fixture now uses the same DPI, visual-style and typography initialization as the application.

Fixed findings
1. Major: in small windows the picker squeezed monitoring controls into an unreadable column. It now occupies the workspace width when necessary, retains scrolling to its footer, and restores the dashboard on close. Desktop docking is checked for non-overlap.
2. Major: name/relink dialogs had sparse dock-only layouts with missing Cancel actions. Module-owned native dialogs now have labels, spacing, aligned commands, Enter/Escape behavior and disabled confirmation for invalid or missing selections.
3. Minor: unread or nonnumeric chart series created empty axes. Only numeric series allocate axes; an empty trend explains how to obtain numeric readings. Single numeric samples show a point. Legends are shortened with full tooltips, and distinct units keep distinct axes.
4. Minor: table columns could collapse until headers/values were unreadable. Columns now have readable minimum widths and use native horizontal scrolling when needed; the table no longer starts with a selected cell.
5. Minor: long card names, meter names, values and errors were clipped with no recovery. Full text is now available through tooltips. The original card layout and saved sizes remain intact.
6. Minor: picker fields lacked accessible names and no-match/no-object guidance. Labels/accessibility metadata, clear empty-state explanations and input order are now explicit.
7. Minor: a disabled primary button retained a blue background with gray text. Disabled dashboard buttons now use the native disabled fill/text treatment.
8. Minor: layout editing had no visible completion state or keyboard reordering/resizing. Edit layout changes to Done. Focused cards accept Ctrl+arrows to move, Ctrl+Shift+arrows to resize, and Escape exits editing or closes the picker. Corner deletion retains a solid focus indicator.
9. Minor: chart headings could overlap or clip when commands wrapped. Headings wrap within the card, reserve delete space and avoid zero-height chart layout during construction.

Preserved decisions
Dashboards remain embedded beside Devices. No toolbar/View dashboard shortcut or Objects/Dashboards tab was reintroduced. Add OBIS retains its label without a plus. The workspace subtitle stays removed. Drag/drop, saved sizes/order, hover deletion, multi-meter bindings, all-object selection and availability explanations remain. Settings enable/disable remains restart-based. All feature code stays in the optional module; Gurux.DLMS remains the same package and binary.
